layer. ACC Section 22 built the approval engine for finance documents; this section generalizes it as the platform service all Books use, and catalogs every workflow so none 
exists as bespoke code. No module may implement its own approval or notification mechanism. W.1	Approval	Workflow	Engine Element Specification Definition model Per 
document type: trigger (submit, threshold breach, field-change class), condition rules (value bands, return class, margin floor delta, warranty flag, entity — any document field 
via the rule grammar), approver chain (sequential steps; each step = role, named user, or derived owner such as Cost Center Manager), parallel steps where flagged (CCB votes), and 
terminal actions (status transition, posting release, document generation)

3. RMA — Return from Customer PE Transformer’s customer return process is the RMA process. No customer material enters any PE warehouse without an approved RMA number. The RMA 
module replaces the bare “Return from Customer” transaction stub: the inventory movement specified in the gap register (DR Return Inventory / CR COGS reversal) becomes one step 
inside a controlled, end-to-end process that also handles warranty determination, inspection, disposition, credit memos, repairs, replacements and field returns of installed 
transformers. 3.1 Return Classes Class Typical Case Key Differences RC1 — Component / distribution return PE Grid Components customer returns bushings, arresters, hardware bought 
from stock Standard receipt into quarantine; restocking fee rules apply; credit or replacement; fastest path RC2 — Finished transformer, not yet energized Unit refused at delivery, 
damaged in transit, wrong configuration shipped Serialized; freight and crating logistics; transit-damage insurance claim fields; full inspection RC3 — Field return of installed / 
energized unit Warranty failure at substation; unit de-energized and returned for teardown or repair Warranty adjudication from serial record; oil handling and hazmat transport; 
teardown inspection; repair order or replacement unit; failure analysis feeding NCR/CAPA RC4 — Return for billable repair / refurbishment Out-of-warranty unit sent in for repair at 
customer cost No credit; generates a billable Repair Order and a service invoice (4150 Service & Repair Revenue)  3.2 End-to-End Process Flow 1. Request. Customer service creates 
the RMA from the originating document (invoice, sales order or shipped serial). System pulls customer, item, serial/batch, ship date, warranty status. If no reference document 
exists, the No-Reference exception path (§3.9) applies. 2. Approval. Approval routing per RMA policy matrix (§3.10): value threshold, return class and warranty claim flag decide the 
approver chain (Customer Service Manager, then Quality Manager for RC3, then Controller above $50,000 expected credit). 3. Authorization issued. RMA number and return instructions 
(PDF) are emailed to the customer: RMA barcode label to affix, ship-to dock, freight terms (who pays per policy), packaging/oil handling instructions for RC3. 4. Return receipt. 
Receiving scans the RMA barcode; the receipt screen (a Check-In of Receipt Type “Return Receipt”, DELTA to INV 5.1) is pre-populated from RMA lines. All returned stock lands in the 
Quarantine warehouse with quality status QI Hold, GL account 1335 Return/RMA Inventory. Serial status moves to Returned. 5. Inspection. A Return Inspection (Quality module, 
reusing the Incoming Inspection engine INV 6.1 with plan type = RMA) is auto-created per line. For RC3, the teardown checklist applies and photographs are mandatory attachments. 
6. Disposition. Inspector proposes, authorized role approves: Restock / Repair / Replace / Scrap / Return to Customer As-Is. Warranty claims additionally get Warranty Approved or 
Warranty Denied. 7. Settlement. Depending on disposition: credit memo request → ACC credit note (ACC Section 4); replacement sales order at zero price with reference; repair order 
(rework production order, Part D §9) either under 2610 Warranty Reserve or billable; scrap posting; or return shipment to customer. 8. Closure. RMA closes when every line reaches a 
terminal disposition and all financial documents are posted. Closure is blocked while any linked document (credit note, WO, replacement SO) is open.
