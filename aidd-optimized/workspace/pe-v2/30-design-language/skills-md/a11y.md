# SEED - accessibility floor - pe-v2 (Phase 2A)

> **What this is.** The accessibility rules every screen of the transformer ERP must meet, in
> the office and on the shop floor. It overrides every other design file. It is for the prototype
> builder, the designer who takes over, and anyone reviewing a build.
>
> **Where it stands.** Seed, 9 October 2026, first version. Unlike the other four seed files, this
> one is not provisional: the floor does not depend on the visual style, so it survives when the
> user's design language arrives.
>
> **What we need from you.** Nothing now. If a sector or procurement standard raises the floor
> above WCAG 2.2 AA, tell us; none is known.

**Precedence.** This file overrides `tokens.md`, `type.md`, `layout.md` and `color.md`, and every
2B file. Where a style rule and this file conflict, this file wins and the conflict is escalated,
never settled by lowering the floor (GUARDRAILS 11). `shared-specs/EngineeringSpec.md` wins on
code structure only.

**Level.** WCAG 2.2 AA. PROJECT_CONFIG records `accessibility_level: AA` and no known driver
raising it (risk R-A11Y open).

## 1. The floor

| # | Rule | Checked by | Example violation |
|---|---|---|---|
| *A-1* | *Status, scan result and validation are never carried by colour alone: status word plus icon plus fill style (`color.md` C-2)* | *Greyscale screenshot: every state still identifiable* | *A red row with no text saying why* |
| A-2 | Text contrast 4.5:1, large text (24 px, or 18.66 px bold) 3:1, in both themes and in hover, focus, active, disabled-with-meaning states | Contrast table in `color.md` section 3 plus a spot check of the build | Amber #B58221 text on white (3.40:1) |
| A-3 | Every task completable by keyboard alone; tab order follows reading order | Unplug the mouse, run the task | A row action reachable only on hover |
| A-4 | Focus always visible: 2 px `--ring` with 2 px offset; never `outline-none` without the ring | Tab through the screen | shadcn class edited to drop `focus-visible:ring` |
| A-5 | Focus not hidden by sticky headers, the action bar or banners (WCAG 2.4.11) | Tab to the last row under a sticky footer | Focused row behind the kiosk action bar |
| A-6 | Control boundaries and meaningful icons 3:1 against their background | `color.md` table, `--input` row | Input with a #E5E5E5 border |
| A-7 | Targets at least 24 x 24 px office; at least 48 x 48 px on floor-touch, the specification's figure [DOC:p.241 §8.4] (asserted), above the 44 px touch floor | Measure in dev tools | A 32 px button on the Shop Floor Terminal |
| A-8 | Nothing flashes more than 3 times per second; the scan success flash is one flash, at most 400 ms | Record the screen, count frames | A row that blinks until acknowledged |
| A-9 | `prefers-reduced-motion`: the scan flash becomes a static `--scan-success-bg` row plus the `Check` icon, held 2 s | Toggle the OS setting | Flash still animates with reduced motion on |
| A-10 | Every input has a visible label; placeholder text is never the label | Inspect each field | Scan field labelled only by placeholder "Scan..." |
| A-11 | Errors name the field and the fix, inline and in a summary at the top of the form | Submit an empty required field | Red border with no message |
| A-12 | Status changes, scan results and the offline banner are announced: `role="status"` for success and offline, `role="alert"` for scan failure | Screen reader on the kiosk build | Scan failure shown but not announced |
| A-13 | Dragging is never the only way (WCAG 2.5.7): every reorder or move has a button or menu alternative | Try the task without dragging | Routing operations reorderable only by drag |
| A-14 | No re-entry of data the user gave earlier in the same process (WCAG 3.3.7) | Walk a wizard end to end | Wizard asks for the order number twice |
| A-15 | Login needs no memory or puzzle test (WCAG 3.3.8); badge-scan login on kiosks meets this [DOC:p.238 §8.2] (asserted) | Review login screens | A CAPTCHA on login |

## 2. Shop-floor obligations

These come from the specification and sit on top of the floor.

- Scan feedback within 400 ms, with sound and a visual change together [DOC:p.241 §8.4] (asserted).
  **Rule A-16:** the visual change carries text ("Scanned" or the failure reason); sound is never
  the only signal, because the floor is loud.
- No silent failures and no toast that disappears before a gloved operator looks up
  [DOC:p.241 §8.4] (asserted). **Rule A-17:** scan failure banners stay until the next scan or an
  explicit dismiss; a Sonner toast for a scan failure is a violation.
- Offline is visible: persistent banner with queue depth, up to 4 h of queued scans
  [DOC:p.241 §8.4] (asserted). **Rule A-18:** the banner is text plus icon, never colour alone.
- Test with gloves at arm's length [DOC:p.241 §8.4] (asserted). **Rule A-19:** every floor-touch
  screen in a usability round is attempted wearing work gloves, standing.
- Scanners enter data as keyboard input through the wedge service [DOC:p.238 §8.2] (asserted).
  **Rule A-20:** the scan field is a native `<input>` that keeps focus after each scan, so a
  scanner and a keyboard both work; nothing traps focus elsewhere on a scan screen.

## 3. Component rules that matter early

- Use shadcn/Radix primitives as shipped for Dialog, Popover, DropdownMenu, Select, Tabs, Tooltip;
  they carry the keyboard and focus patterns. Rebuilding one from a `div` is a violation.
- Tooltips never hold the only copy of information on floor-touch screens (no hover there).
- Read-only records (terminal statuses, view-only roles [DOC:p.242 §10.3] (asserted)) render
  values as text, not as disabled inputs, so they keep full contrast and stay readable.

## 4. Testing ladder (state the method with every claim)

1. Automated scan (axe DevTools) on every screen state. An automated scan alone is never reported
   as an accessibility assessment.
2. Keyboard-only pass of each primary task.
3. Screen reader pass (NVDA on Windows desktop, TalkBack on the TC77) of the primary tasks.
4. Greyscale and 200% zoom pass; gloved, standing pass on floor-touch screens.

## 5. Recorded exceptions

None.
