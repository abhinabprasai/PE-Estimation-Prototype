# 10-discovery/: Phase 1 output

Owner: discovery-lead. Sequence: spec-intake, anchor-analysis, glossary-builder,
question-generation, the call, interview-facilitation, contradiction-mining, written
confirmation.

| File | Skill | Notes |
|---|---|---|
| `anchor-analysis.md` | anchor-analysis | Terms, processes, asserted gaps, commitments, silences, internal contradictions |
| `glossary.md` | glossary-builder | Term, definition, class (descriptive / rule-bearing), tag, verified-by. Binds every label in the product |
| `questions.md` | question-generation | Four groups, laddered, answerer-tagged, with a share-version at the top |
| `transcripts/{date}.md` | interview-facilitation | Three-column capture: [PO] [DA] [TEAM], plus SOLUTIONS-OFFERED and NEW-TERMS |
| `problem-statements.md` | contradiction-mining | Problem, tag, workaround, downstream consequence, confidence |
| `solution-hypotheses.md` | interview-facilitation | Solutions offered from experience. Consulted, never merged into the problem set |
| `open-questions.md` | all | Becomes the Phase 2A research plan. DA-ONLY items flagged |
| `derived-brief.md` | spec-intake | Only when the project began without a spec. Signed, it becomes the anchor document |

## Phase 1 exits when

Written confirmation of the problem set from the domain authority (a verbal yes is (asserted) and
does not close the phase), zero owner-less contradictions, and `open-questions.md` converted into
a research plan.

Delete this file once the folder holds real artifacts.

---

**Key.**
`[DA]` domain authority, the person who rules on how the business actually works - `[PO]` product owner - `[USER:role]` an end user in that role - `[TEAM]` someone on our team - `[DOC:section]` your own document - `[RESEARCH:source]` outside research - `[LLM]` inferred by a model, not verified by anyone.
`(confirmed)` the domain authority verified it, on record - `(asserted)` a human said it once - `(inferred)` nobody has said it.
