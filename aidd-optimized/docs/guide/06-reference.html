Part 8Reference

The dependency order, the guardrails in summary, troubleshooting, extension rules, and a glossary of the system's own vocabulary.

8.1 Artifact dependency order

Used for staleness checks and rework regeneration. A -> B means B reads from A, so a change to A stales B.

spec-intake → {anchor-doc | derived-brief} → problem-statements → refined-requirements → {to-be, erd, breakdown} spec-intake → assumptions (live; every artifact resting on one names its ASM-ID) transcripts → problem-statements problem-statements + open-questions → research-plan → kb kb → {prd-draft, prompts, style-guide, dummy-content} prompts + style-guide → prototype as-is → to-be → flow-optimization → ia → {userflows, sitemap} erd → {ia, userflows, status-mapping, component state matrices} erd (statuses) + incumbents (density) → style-guide → skills-md → {prompts, hifi} refined-requirements + prioritized-list → hifi hifi → design-critique → gate shared-specs (.md loop) → prompts + style-guide (next project)
Two staleness paths that are easy to miss

A change to the ERD's status list stales the style guide's status encoding map, every component state matrix that displays it, and every hi-fi screen state derived from it.

A change to the IA stales every userflow, the sitemap, and usually the route scheme.

The fourteen escalation triggers

An agent stops and asks a human when: (1) no domain authority is identified and Phase 1 work is requested; (2) an [LLM]-only rule is about to enter a design artifact; (3) a gate would be held without required attendance; (4) three or more Type Bs trace to one Phase 1 topic; (5) the prototype timebox is exceeded or hi-fi from the prototype is proposed; (6) a fixed-bid list change is requested after Gate 2; (7) the document and the authority disagree on something a current task depends on, with no owner; (8) shared-specs are more than one project old and unreviewed and a prompt is about to consume them; (9) a behaviour-constraining assumption is about to pass Gate 2 unresolved; (10) a design floor item would be violated or traded away; (11) a design needs a status the ERD lacks or an affordance the lifecycle forbids; (12) Phase 0 is being skipped; (13) the assumption register has not shrunk between two consecutive gates; (14) a gate would be held on a stale conformance snapshot, unresolved blocking findings, or ghost behaviour inside a signed artifact.

8.3 Troubleshooting

SymptomWhat it usually means, and what to do
Gate 1 produced almost no corrections Not a pass. Either the set was too safe or the reviewer was polite. Run the three probes before accepting it, and record that you did. If the set genuinely was too safe, the tentative artifacts were probably too polished.
The same correction keeps coming back at successive gates The correction was classified Type A when it was Type B, so it was patched in one artifact while the requirement stayed wrong. Re-classify and route through the reconciler; then check whether post-gate verification is being run at all.
Developers ask questions the artifacts already answer The walkthrough was a survey rather than a depth walk, or the routing rule was stated but not demonstrated. Track the question split; it will show which. Feed the clusters into the loop review as candidate rules.
New statuses keep appearing in Phase 3 The exhaustion protocol was not run with the DA, or was run from memory. Each new status is a Type B and a missing screen. Re-run the status pass on the affected entities before speccing more features.
The assumption register never shrinks Nobody is chasing answers. This is an escalation trigger in its own right (GUARDRAILS 9.13). Take the overdue entries to the DA as a batch with their blast radii attached.
Every design discussion is about taste The style guide has aspirations rather than rules. Apply the violation-checkable test to each line and rewrite or delete. A critique with no rules to cite produces only opinions.
The prioritized list has become all Must The mandatory partition was not audited against authority classes. Only law and contract are automatically mandatory; policy and preference compete. Re-run the audit and re-trade.
The team is answering domain questions from memory The KB is being bypassed. kb-curator names the pattern; the fix is to route the questions through the KB and let it say "cannot answer", which sends them to open-questions where they belong.
Conformance snapshots keep coming back clean, which feels wrong Sample an artifact that has not appeared in a finding for two snapshots. Either it is genuinely clean or the sweeps are not really reading it; the sample tells you which.
A client wants to skip Phase 1 because "we know what we want" Run intake anyway; it takes an hour. The audit scorecard is the conversation: it shows, dimension by dimension, what is actually specified. Four or more ABSENTs is not an argument, it is a measurement.

8.5 Extending the system

Adding a skill

  1. Create .claude/skills/{name}/SKILL.md with frontmatter carrying a description that states what it does and when to use it; that sentence is what triggers it.
  2. Follow the standard anatomy (5.1). Keep it under about 300 lines; put reusable banks, tables and numbers in references/.
  3. Add it to an agent's skills: list.
  4. If it changes who does what, add a routing row to CLAUDE.md section 4.
  5. If it produces an artifact, add it to the dependency order (section 5) and to the workspace placeholder for its folder.
  6. Add a row to docs/SKILL-INDEX.md.

Adding an agent

  1. Create .claude/agents/{name}.md with name, description (including when to use it proactively), tools, and skills.
  2. Include all six body sections: goal, operating rules, handoff contract table, quality bar, conformance participation, escalations. The handoff table is what keeps the chain working without the orchestrator remembering.
  3. Add routing rows to CLAUDE.md, and name the seams: what must be settled before this agent starts, and what it must not do that belongs to a neighbour.

Changing a guardrail

Guardrails live in one file, referenced everywhere, so a rule change happens once. Do not copy a guardrail into a skill; cite it by number. If a guardrail needs an exception for a project, that is a PROJECT_CONFIG variable with a routing effect, not a local override.

8.6 Glossary of system terms

TermMeaning
Anchor documentThe document the project treats as its starting statement of requirements. Superseded, never edited, by the refined requirement document at Phase 2B
Assumption registerThe live list of what the project is assuming, each with blast radius, cheapest test, owner and decision date
Blast radiusWhat becomes wrong if an assumption is false: which artifacts, which screens, and which rework class
Consequences noteThe ERD's one-line-per-rule translation of lifecycle and permission constraints into interface obligations
Derived briefThe reconstructed specification produced when no spec was supplied. Signed, it becomes the anchor document
Domain authority (DA)The person who can rule on domain correctness. Without one, Phase 1 cannot converge
GhostArtifact behaviour citing no requirement. Either a missing requirement or invention
OrphanA requirement no artifact implements. Either awaiting its phase, descoped, or forgotten
Pain indexThe per-flow rollup (manual movements, uncaught errors, waits, uncommunicated crossings, systems touched) that a to-be must beat
Rule-bearing termA glossary term whose definition constrains behaviour. Getting it wrong is expensive and silent
Second-job checkAsking what invisible work a step does (control, audit, training, signalling) before eliminating it
SilenceSomething the anchor document does not cover. A finding, and the seed of the exceptions question group
Spec slot00-inputs/PRD.md: the client's spec verbatim or the completed placeholder. Never absent
Tentative setThe deliberately rough Phase 2A structure artifacts, built to be corrected at Gate 1
Type A / Type BSurface correction (patch in place) versus structural correction (route through the reconciler first)
Verification agendaThe anchor analysis output ordering commitments by blast radius, which question generation prioritizes from
