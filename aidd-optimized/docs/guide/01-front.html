Part 1Orientation

What this system is, the ideas it rests on, the shape of the process, and how to start a project in the next ten minutes.

1.1 What this system is

An agentic implementation of the AI-Augmented Discovery and Design process: a three-phase, gate-controlled product design workflow built for domain-heavy projects, where the cost of misunderstanding the client's rules is far higher than the cost of drawing the wrong screen.

You talk to the orchestrator, which is the main session. It routes work to specialist agents. Agents load skills. Skills carry the craft: the procedures, the decision tables, the probing banks, the failure modes. Nothing advances past a gate without that gate's exit criteria met and its report filed, and a standing conformance engine continuously checks that every artifact still agrees with the documents it derives from.

Everything is plain markdown. It can be dropped into a repository and used directly with Claude Code, or read by any agent runtime that understands markdown instructions, or used by humans with no agent at all: the templates, the provenance tags and the gate reports work identically.

1.2 The five ideas it is built on

1. Provenance is the load-bearing wall

Every claim about the client's world carries a source tag and a confidence marker. Most failure modes of a discovery process are attribution collapse: six weeks in, nobody can say whether "the system must lock the record after posting" came from the domain authority, from the anchor document, from an industry convention, or from a model's plausible guess. Once that distinction is lost it cannot be recovered, and every downstream decision inherits an unknown risk.

2. Gates are the only thing that stops work

Three formal gates, each with required attendees, written exit criteria and a filed report. A gate held without its required attendees is recorded as NOT HELD, whatever happened in the room. This strictness is the point: a process whose checkpoints can be waved through has checkpoints that mean nothing.

3. The prototype is an interview instrument, not a preview

Phase 2A produces a throwaway prototype whose success is measured in corrections produced, not approval received. It is built to be wrong in a useful way, framed that way out loud, and archived immediately after Gate 1. Hi-fi never starts from its screens.

4. One document reconciles everything

The refined requirement document does not restate the client's spec; it shows where the spec and the domain authority disagreed and why the resolution won. Its rationale column is the answer to "why does this rule work this way" for the life of the product. Every structural correction, from any source and at any time, passes through it before any artifact is edited.

5. The loop pays the next project

At close, a developer and a designer review three shared specification files against what the project actually built. Those files are consumed by the next project's prototype prompts, so generated output matches real team conventions and can be re-used rather than referenced. It is the only step that pays out later rather than now, which makes it the easiest to skip and the most expensive to have skipped.

1.3 The process at a glance

PHASE 0 Intake Classify what actually arrived. Fill the spec slot. Open the assumption register. | PHASE 1 Empathize + Define Anchor analysis, glossary, questions, the D&D call, contradiction mining. GATE Written confirmation of the problem set by the DA. | PHASE 2A Initial Design Parallel: research, knowledge base, as-is flows, style seed, prompts, throwaway prototype. GATE 1 DA + PO. The set reviewed together, never piecemeal. Heavy correction = success. Prototype archived. | PHASE 2B Further Design Refined requirements -> ERD -> to-be flows -> breakdown -> flow optimization -> IA -> userflows -> prioritized feature list (signed). GATE 2 DA + PO + developer. Model first, screens last. List locks on fixed-bid engagements. | PHASE 3 Test + Prototype Hi-fi specs for prioritized features only: every state, dev notes, interactions, status mapping, real copy, realistic content. GATE 3 Internal, line by line against requirements. Then client validation. | HANDOFF Transfer + Loop Full artifact set, live walkthrough with the dev team, md-spec loop updating shared-specs and recording the three cross-project metrics.

Two properties of this shape are worth naming. First, the Test stage re-opens the problem space: corrections found late are routed backward through the requirement document, never absorbed silently into a screen. Second, the phases are deliberately front-loaded. Phase 3 designs only what the prioritized list contains, and that narrowing is what pays for the investment in Phases 1 and 2.

1.4 Quick start

Starting a new project

# in the repository root, with Claude Code running
/new-project acme-invoicing

The orchestrator copies workspace/_TEMPLATE/, then asks for the five adaptation variables plus two the design layer needs (accessibility obligation, and device and environment per role). Answer honestly; they change how the whole process routes. Do not guess the domain authority: if nobody knows who can rule on correctness, that is the first thing to find out, and Phase 1 blocks until you do.

Immediately after, intake runs:

/intake-spec

Give it whatever you have: a PRD, a gap document, a slide deck, a login to the old system, or nothing at all. It classifies what arrived, audits it against fourteen dimensions, fills the spec slot at 00-inputs/PRD.md, and starts a substitute path if there is no real spec.

Joining a project already running

/phase-status

The standup view: current phase, open blockers, next gate and its unmet exit criteria, stale artifacts with the dependency that staled them, the conformance headline, and the next three concrete actions with their owning agents.

The one habit that matters most

When you paste notes, forward an email, or relay a call, say who said what. The system can do nothing honest with "the client wants X". It can do a great deal with "[DA] said X on 14 March, and [DOC:4.2] says the opposite".
